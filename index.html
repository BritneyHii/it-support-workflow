境外产研 IT 支持工单定级与跟进机制

明确问题等级、核心动作、跟进频率、结果时限及升级节点， 确保问题有人跟、按时跟、持续跟，直至业务方确认闭环。

⏱️ 一、跟进时间与核心机制

核心原则：从问题首次反馈开始计时，IT 支持全程督办。
首次响应 ≠ 完成跟进。问题未解决期间，IT 支持需按照对应等级的固定频率推进； 到达跟进节点仍无反馈或无突破时，立即按照升级机制处理。

📌 二、时间节点怎么理解

核心动作 收到问题后，IT 支持第一时间需要执行的关键操作，如拉群、拉会、建单指派等。
跟进频率 问题未解决期间，IT 支持确认进展的最低频率。
结果时限 要求在规定时间内给出明确结论、临时方案或最终解决方案。
特别说明： IT 支持需要 @提醒；仍无响应，则按照升级机制继续推进。

🔄 三、统一跟进流程

1
问题反馈 记录首次反馈时间
2
完成定级 确认 P0 / P1 / P2
3
核心动作 按等级要求执行关键操作
4
持续跟进 按固定频率推进
5
确认闭环 业务方确认后正式结案

📊 四、问题定级标准

定级原则：先看影响范围，再看业务阻断程度。
满足对应等级任一条件，即按对应等级处理；问题严重程度发生变化时，及时调整等级。

📈 六、升级机制

① 等级升级｜问题变严重

P2 → P1
超 5 天无解决方案 / 出现客诉 / 校长介入 / 业务累计催促 3 次
P1 → P0
超 24 小时无方案且无临时兜底 / 出现重大客诉或舆情 / 故障持续扩大

② 找人升级｜推进不动

P0： 30 分钟未止损 → 升级至团队负责人协调推动
P1： 15 分钟无人承接 → 升级研发 +1 负责人； 12 小时无突破 → 升级至团队负责人
P2： 当天无响应 → 找当前跟进人； 超期无结果 → 升级研发 +1 负责人

✅ 七、统一闭环规则

问题解决 ≠ 工单结案

技术修复完成后，必须经反馈人 / 业务方确认实际问题已解决， 才算正式结案。禁止技术侧单方面宣布“已解决”后直接关闭工单。
